                          1.1 Tools: the terminal, git, Python and tests

                          Most poker bots don't lose to better poker. They lose to a crash, a stray print, or a branch nobody merged.

                          1.1.1 The terminal in one minute

                          A shell runs commands. Every command has three byte streams: standard input (in), standard output (out) and standard error (diagnostics). Every command also ends with an exit code: 0 means success.

                          Key idea

                          Our bot is a command. The engine writes JSON lines to its stdin and reads replies from its stdout. A stray print() on stdout corrupts the conversation, so debug text goes to stderr.

                          1.1.2 Git, as a subway map

                          Forget the commands for a moment. Git stores snapshots:

                          • a blob is one file's bytes, a tree is a folder listing, and a commit is a snapshot plus a message plus its parent(s);
                          • everything is named by a hash of its content. Change one byte and every hash above it changes, so 3f61900 pins the whole project and its history. Commits form a directed acyclic graph;
                          • a branch is just a sticky note on one commit, and HEAD means "you are here".

                          A file lives in three places: the working tree (your editor), the index (what the next commit will hold) and the last commit. git add copies working tree → index; git commit turns the index into a commit. A .gitignore lists files git should ignore, and later rules win. Because git never looks inside an ignored folder, keeping one subfolder takes data/* then !data/keep/.

                          MoveWhat really happens
                          Fast-forwardnothing new on main since you branched: the label just slides forward
                          Three-way mergecompare both sides with the merge base; changes on one side are taken, and different changes to the same lines are a merge conflict you resolve by hand
                          Rebasereplay your commits on a new base: new hashes, a straight line; never on shared commits
                          force-pushoverwrite the remote's history. Don't.

                          A remote (origin) is another copy of the repository. Remote-tracking branches such as origin/main are your last snapshot of it: fetch refreshes them, push uploads, and pull = fetch + merge. A pull request is a reviewed merge proposal. Continuous integration (CI) runs the tests on a clean machine at every push.

                          Pitfall

                          Local main ≠ origin/main. In this project an assistant once declared a branch "missing from main" while comparing against a stale copy: another session had merged it an hour earlier. Fetch first.

                          1.1.3 Python projects

                          The competition runs Python 3.11, with only the standard library, NumPy and SciPy. A virtual environment (.venv/) holds one project's packages. A requirements file with pinning (numpy==2.3.4) makes every machine install the same thing. A module is one .py file; a package is a folder of them.

                          1.1.4 Tests that can actually fail

                          • A unit test asserts one behaviour. pytest has markers (@slow), parametrisation (one test, many inputs) and -n auto (all cores).
                          • Tests must be deterministic: fix every random seed. Code that samples "until 50 ms pass" makes tests flaky under load; bound by counts instead.
                          • Expected values come from somewhere independent. A tautological test recomputes the answer the way the code does, so it can never fail.
                          • Test-driven development: watch the test go red first. That proves it can catch the bug.

                          1.1.5 NumPy, vectorisation, GPUs

                          A Python loop costs about 50 ns per step; NumPy runs whole arrays in C, often 20–100× faster. Vectorisation means replacing loops with array operations: elementwise maths, broadcasting (shape (n,1)(n,1) with (1,m)(1,m) behaves like (n,m)(n,m)), reductions and matrix products AxA\mathbf{x}. A GPU is the extreme version: brilliant for big regular arrays, terrible for branchy tree walks.

                          1.1.6 Processes and the clock

                          The engine runs our bot as a separate process. If it crashes or replies too slowly, we forfeit the match. A time bank is a budget of seconds for the whole match. A signal alarm (setitimer) can interrupt a computation that runs too long: our hard deadline. Remember that alarm; it comes back as a bug in Chapter 2.

                          1.2 Probability: the five facts we keep using

                          Poker is a game where you can play perfectly and lose, or badly and win. Statistics is how you tell the difference.

                          1.2.1 Expectation, variance, Bayes

                          A random variable XX (the chips won in one hand) has an expectation, its long-run average, and expectation is linear, always:

                          E[aX+bY]=a E[X]+b E[Y]. \mathbb{E}[aX + bY] = a\,\mathbb{E}[X] + b\,\mathbb{E}[Y].

                          The variance measures spread, and its root is the standard deviation σ\sigma. For sums, the covariance term is the one to watch:

                          Var⁡(X+Y)=Var⁡X+Var⁡Y+2Cov⁡(X,Y). \operatorname{Var}(X+Y) = \operatorname{Var}X + \operatorname{Var}Y + 2\operatorname{Cov}(X,Y).

                          Conditional probability P(A∣B)=P(A∩B)/P(B)P(A\mid B)=P(A\cap B)/P(B) leads to Bayes' rule, the detective's formula. In odds form:

                          P(H1∣D)P(H0∣D)⏟posterior odds  =  P(D∣H1)P(D∣H0)⏟likelihood ratio×P(H1)P(H0)⏟prior odds \underbrace{\frac{P(H_1\mid D)}{P(H_0\mid D)}}_{\text{posterior odds}} \;=\; \underbrace{\frac{P(D\mid H_1)}{P(D\mid H_0)}}_{\text{likelihood ratio}} \times \underbrace{\frac{P(H_1)}{P(H_0)}}_{\text{prior odds}}

                          The prior is what you believed before, the likelihood is how well each story explains the data, and the posterior is what you believe now. Independent clues multiply, so their logs add: the log-likelihood ratio is an evidence counter you keep a running total of.

                          1.2.2 Why one match proves nothing

                          Average nn hands with spread σ\sigma. The law of large numbers says the average converges, and the central limit theorem says it is roughly normal, with standard error

                          SE=σn,95% confidence interval≈Xˉ±1.96 SE. \mathrm{SE} = \frac{\sigma}{\sqrt{n}}, \qquad \text{95\% confidence interval} \approx \bar X \pm 1.96\,\mathrm{SE}.

                          1.2.3 How many hands? And the multiple-testing trap

                          To spot a true edge δ\delta with a 2-SE test and 80% power:

                          n≈((2+0.84) σδ)2⇒δ=1: n≈20,000 hands. n \approx \left(\frac{(2+0.84)\,\sigma}{\delta}\right)^{2} \quad\Rightarrow\quad \delta = 1:\ n \approx 20{,}000 \text{ hands}.

                          A false positive celebrates noise; a false negative misses a real gain.

                          Pitfall: 20 tries, one "winner"

                          Test 20 useless tweaks at 2 SE and there's a 1−0.97720≈37%1-0.977^{20}\approx 37\% chance one "passes". Its measured gain is inflated: the winner's curse. Cures: re-test on fresh seeds, a stricter bar when you try many (Bonferroni correction), and a held-out set.

                          1.3 Monte Carlo and the duplicate trick

                          1.3.1 Monte Carlo

                          Monte Carlo: can't compute it? Sample it. Deal the unknown cards 1,000 times and count wins; the error is p(1−p)/n≈1.6\sqrt{p(1-p)/n}\approx 1.6 points. Importance sampling samples from a handier qq and reweights:

                          Ep[f]=Eq ⁣[f pq] \mathbb{E}_p[f] = \mathbb{E}_q\!\left[f\,\frac{p}{q}\right]

                          It is unbiased, but explosive when qq rarely visits where pp lives. Remember this when MCCFR shows up.

                          1.3.2 Duplicate deals

                          Most of poker's noise is the cards. Duplicate play deals every hand twice with the seats swapped, so your good cards in one playing are your bad cards in the other. The covariance is negative and the noise cancels:

                          Var⁡(X1+X2)=Var⁡X1+Var⁡X2+2Cov⁡(X1,X2)⏟< 0. \operatorname{Var}(X_1+X_2)=\operatorname{Var}X_1+\operatorname{Var}X_2+2\underbrace{\operatorname{Cov}(X_1,X_2)}_{<\,0}.

                          Same idea for comparing bots: play A and B against the same opponent on the same seeds (common random numbers). A control variate subtracts known-mean luck, such as all-in equity, for the same effect.

                          1.4 Learning while you play

                          Hand 37. The opponent just folded again. Is that a pattern, or bad luck?

                          1.4.1 Shrink small samples

                          Three folds in four tries is not "75%". Put a Beta prior on the rate: it behaves like KK imaginary observations with mean mm. Then the estimate is a shrinkage toward the prior:

                          p^=k+Kmn+K(k=3, n=4, m=0.4, K=15  ⇒  p^=0.47). \hat p = \frac{k + K m}{n + K} \qquad \bigl(k=3,\ n=4,\ m=0.4,\ K=15 \;\Rightarrow\; \hat p = 0.47\bigr).

                          1.4.2 Decide as early as possible: the SPRT

                          Wald's sequential probability ratio test keeps a running log-likelihood ratio Λt\Lambda_t and stops at the first boundary it crosses:

                          Λt=∑s≤tlog⁡P(ds∣H1)P(ds∣H0) \Lambda_t=\sum_{s\le t}\log\frac{P(d_s\mid H_1)}{P(d_s\mid H_0)}
                          stop whenΛt≥log⁡1−βαorΛt≤log⁡β1−α. \text{stop when}\quad \Lambda_t \ge \log\tfrac{1-\beta}{\alpha}\quad\text{or}\quad \Lambda_t \le \log\tfrac{\beta}{1-\alpha}.

                          No test with the same error rates is faster on average. The expected wait is set by the Kullback–Leibler divergence, the evidence each observation brings:

                          E[N]≈(1−β)log⁡1−βα+βlog⁡β1−αKL(H1 ∥ H0) \mathbb{E}[N]\approx\frac{(1-\beta)\log\frac{1-\beta}{\alpha}+\beta\log\frac{\beta}{1-\alpha}}{\mathrm{KL}(H_1\,\|\,H_0)}
                          KL(p ∥ q)=∑xp(x)log⁡p(x)q(x). \mathrm{KL}(p\,\|\,q)=\sum_x p(x)\log\frac{p(x)}{q(x)}.

                          Example. "Folds 60%" vs "folds 40%": KL = 0.192 nats, so about 14 bets to decide at 5% error. If you only bet into them every tenth hand, that's 140 hands. Detection speed = evidence per event × events per hand.

                          1.4.3 Many suspects: naive Bayes

                          With KK candidate opponent types, keep one log-score per type and turn the scores into probabilities with a softmax:

                          Sk=log⁡P(k)+∑tlog⁡P(dt∣k),P(k∣data)=eSk∑jeSj. S_k=\log P(k)+\sum_t\log P(d_t\mid k),\qquad P(k\mid\text{data})=\frac{e^{S_k}}{\sum_j e^{S_j}}.

                          Assuming the clues are independent is the naive Bayes shortcut: it makes the probabilities over-confident, but the ranking usually comes out right. Laplace (add-one) smoothing keeps one surprising action from ruling a type out forever.

                          Key idea

                          Evidence adds in log space. Shrink small samples. Stop as soon as the evidence is strong (SPRT). To be fast, use every clue, not just one statistic.

                          1.5.2 Discard Hold'em: the twist

                          You get three hole cards. After the flop betting, both players discard one card at the same time, and both discards are shown face up. So you see the flop before choosing your two cards (hand values run closer together), and every discard leaks a little information.

                          1.5.3 Counting hands

                          (522)=1,326\binom{52}{2}=1{,}326 two-card combinations and (523)=22,100\binom{52}{3}=22{,}100 three-card ones. Suit isomorphism (A♠K♠ ≡ A♥K♥ preflop) shrinks these to 169 and 1,755 classes, a lossless squeeze. On a Discard Hold'em river, the opponent holds one of (432)=903\binom{43}{2}=903 hands: the river is a small game.

                          1.5.4 Equity, pot odds, fold equity

                          Equity is your share of the pot at showdown, P(win)+12P(tie)P(\text{win})+\tfrac12 P(\text{tie}). Facing a bet, with pot PP (their bet included) and a call costing cc:

                          EV(call)=e (P+c)−c⟹call iff e>cP+c⏟pot odds. \mathrm{EV}(\text{call}) = e\,(P+c)-c \quad\Longrightarrow\quad \text{call iff } e > \underbrace{\frac{c}{P+c}}_{\text{pot odds}}.

                          A pure bluff of bb into PP breaks even when they fold at least

                          α=bP+b. \alpha = \frac{b}{P+b}.

                          A value bet wants a call from worse hands; a thin one barely does. Real bets mix both reasons:

                          EV(bet)=f P+(1−f)[ecalled (P+2b)−b]. \mathrm{EV}(\text{bet}) = f\,P + (1-f)\bigl[e_{\text{called}}\,(P+2b)-b\bigr].

                          1.5.5 Ranges and the river

                          You never know their cards, only a range of them, updated by Bayes with every action. The river is the purest decision of all: no cards to come. Holding a bluff-catcher, which beats only bluffs:

                          call iff P(bluff∣they bet)>bP+2b(pot-size bet: 33%). \text{call iff } P(\text{bluff}\mid\text{they bet}) > \frac{b}{P+2b}\qquad(\text{pot-size bet: } 33\%).

                          The flip side is the minimum defence frequency: fold more than α\alpha and they profit by betting any two cards, so an unexploitable player continues with at least MDF=PP+b\mathrm{MDF}=\frac{P}{P+b} of their range. Against a player who never bluffs, MDF just throws chips away. That tension drives Section 1.9. Last ratio: the stack-to-pot ratio (SPR); below about 2, every bet is effectively all-in.

                          1.6 Game theory beyond Nash

                          You know Nash equilibrium. Now give the game hidden cards, many moves and a tree a billion nodes deep.

                          1.6.1 Zero-sum: the friendly case

                          Heads-up poker is a two-player zero-sum game. Von Neumann's minimax theorem gives it a single value of the game:

                          max⁡x min⁡y  x⊤ ⁣A y  =  min⁡y max⁡x  x⊤ ⁣A y  =  v. \max_{x}\,\min_{y}\; x^{\top}\!A\,y \;=\; \min_{y}\,\max_{x}\; x^{\top}\!A\,y \;=\; v.
                          • Equilibrium strategies are maximin strategies: they guarantee vv against everyone.
                          • Equilibria are interchangeable: no guessing which one the opponent plays.
                          • With seats alternating and duplicate deals, v=0v=0: an equilibrium bot cannot lose in expectation. It also wins little against weak bots. A fortress, not an attack.

                          1.6.2 Games as trees

                          The extensive form is a tree of histories (everything that has happened so far), with chance nodes for the deals. An information set groups the histories a player can't tell apart, such as "my cards + the board + the betting". A behavioural strategy picks one action distribution per infoset. Poker has perfect recall (nobody forgets), so that is all we need. The reach probability of a history factors by who made each choice:

                          πσ(h)=π1σ(h) π2σ(h) πc(h),π−i=everyone’s share except player i’s. \pi^{\sigma}(h) = \pi_1^{\sigma}(h)\,\pi_2^{\sigma}(h)\,\pi_c(h), \qquad \pi_{-i} = \text{everyone's share except player } i\text{'s}.

                          That factorisation is the engine of CFR.

                          1.6.3 Best response and exploitability

                          A best response is the most profitable reply to a fixed opponent: one tree walk, always a pure strategy. Exploitability is how much best responses would win against a profile, and it is zero exactly at Nash:

                          expl⁡(σ)=12[max⁡σ1′u1(σ1′,σ2)+max⁡σ2′u2(σ1,σ2′)]. \operatorname{expl}(\sigma)=\tfrac12\Bigl[\max_{\sigma_1'}u_1(\sigma_1',\sigma_2)+\max_{\sigma_2'}u_2(\sigma_1,\sigma_2')\Bigr].

                          A profile with expl⁡≤ε\operatorname{expl}\le\varepsilon is an ε-Nash equilibrium. It is measured in milli-big-blinds per hand: here, 1 mbb/hand = 0.002 chips/hand.

                          1.6.4 Kuhn poker: the whole game on one page

                          EquilibriumJQK
                          P1 opensbet α\alpha (bluff)checkbet 3α3\alpha
                          P1 after check–betfoldcall α+13\alpha+\tfrac13call
                          P2 facing a betfoldcall 13\tfrac13call
                          P2 facing a checkbet 13\tfrac13 (bluff)checkbet

                          Here α∈[0,13]\alpha\in[0,\tfrac13], and the value for player 1 is −118-\tfrac1{18}. The magic numbers make the opponent indifferent: P2 bluffs J exactly often enough that P1's Q gains nothing by calling or folding. Indifference is the fingerprint of a mixed equilibrium.

                          1.6.5 What equilibrium won't do

                          If P2 never bluffs, the equilibrium P1 still calls with Q a third of the time and loses every one of those calls. The best response folds. Against real bots, the gap between "equilibrium" and "best response to this bot" is usually much bigger than the equilibrium's own edge. That gap is the case for an exploit layer.

                          1.6.6 The sequence form: poker as a linear programme

                          Swap action probabilities for realisation weights x(s)x(s) of each sequence ss of your own moves. The constraints become linear and the payoff bilinear:

                          x(∅)=1,∑a∈A(I)x(sIa)=x(sI),x≥0    (i.e. Ex=e),payoff =x⊤A y. x(\varnothing)=1,\quad \sum_{a\in A(I)}x(s_I a)=x(s_I),\quad x\ge 0 \;\;(\text{i.e. } Ex=e),\qquad \text{payoff } = x^{\top}A\,y.

                          Dualising the inner minimisation gives a single LP whose size is linear in the tree. This is the sequence form:

                          max⁡x, q  f⊤qs.t.F⊤q≤A⊤x,    Ex=e,    x≥0. \max_{x,\,q}\; f^{\top}q \quad\text{s.t.}\quad F^{\top}q \le A^{\top}x,\;\; Ex=e,\;\; x\ge 0.

                          1.7 Regret, CFR and MCCFR

                          The algorithm behind every superhuman poker bot is, at heart, a robot that keeps a diary of its regrets.

                          1.7.1 Regret

                          Each round you pick a mixed strategy σt\sigma^t, then learn what every action would have paid. Your regret for not always playing aa is:

                          RT(a)=∑t=1T[ut(a)−ut(σt)]. R^T(a)=\sum_{t=1}^{T}\Bigl[u^t(a)-u^t(\sigma^t)\Bigr].

                          This is external regret. An algorithm is no-regret if max⁡aRT(a)/T→0\max_a R^T(a)/T\to 0 against any sequence of payoffs, even an adversarial one.

                          1.7.2 Regret matching

                          Regret matching: play each action in proportion to its positive regret.

                          σT+1(a)=[RT(a)]+∑b[RT(b)]+(uniform if none is positive). \sigma^{T+1}(a)=\frac{\bigl[R^T(a)\bigr]^+}{\sum_b \bigl[R^T(b)\bigr]^+}\qquad(\text{uniform if none is positive}).

                          Against a bot that always plays rock: round 1 is uniform and leaves regrets (0, +1, −1); from round 2 it plays paper every time. One step to the best response.

                          Theorem. With payoffs in a range of width Δ\Delta,

                          max⁡aRT(a)  ≤  Δ∣A∣ T⟹average regret→0 like 1/T. \max_a R^T(a)\;\le\;\Delta\sqrt{|A|\,T}\qquad\Longrightarrow\qquad \text{average regret}\to 0 \text{ like } 1/\sqrt{T}.
                          🔍 Go deeper: the four-line proof

                          Let rt(a)=ut(a)−ut(σt)r^t(a)=u^t(a)-u^t(\sigma^t) and track Φt=∥[Rt]+∥2\Phi_t=\|[R^t]^+\|^2.

                          1. ([x+y]+)2≤([x]++y)2([x+y]^+)^2\le([x]^+ + y)^2, so Φt≤Φt−1+2[Rt−1]+ ⁣⋅rt+∥rt∥2\Phi_t\le\Phi_{t-1}+2[R^{t-1}]^+\!\cdot r^t+\|r^t\|^2.
                          2. The cross term vanishes: σt∝[Rt−1]+\sigma^t\propto[R^{t-1}]^+ and ∑aσt(a) rt(a)=0\sum_a\sigma^t(a)\,r^t(a)=0.
                          3. ∥rt∥2≤∣A∣Δ2\|r^t\|^2\le|A|\Delta^2, so ΦT≤T∣A∣Δ2\Phi_T\le T|A|\Delta^2.
                          4. max⁡aRT(a)≤ΦT≤Δ∣A∣T\max_a R^T(a)\le\sqrt{\Phi_T}\le\Delta\sqrt{|A|T}. ∎

                          1.7.3 Low regret ⇒ equilibrium

                          Let two no-regret learners play each other (self-play). If each has average regret at most ε\varepsilon, their average strategies (xˉ,yˉ)(\bar x,\bar y) form an ε\varepsilon-Nash equilibrium.

                          🔍 Go deeper: why

                          Player 1's bound and the linearity of uu in yy give max⁡x′u(x′,yˉ)≤uˉ+ε\max_{x'}u(x',\bar y)\le\bar u+\varepsilon. Player 2's gives min⁡y′u(xˉ,y′)≥uˉ−ε\min_{y'}u(\bar x,y')\ge\bar u-\varepsilon. Subtract, and the gap (twice the exploitability) is at most 2ε2\varepsilon. ∎

                          Pitfall

                          Ship the average strategy, not the current one.

                          1.7.4 CFR: a regret matcher at every infoset

                          Counterfactual regret minimisation (Zinkevich et al., 2007) runs regret matching at each infoset II. Each history is weighted by how likely chance and the opponent are to bring us there, as if we had steered there on purpose. That is the counterfactual value:

                          vi(σ,I)=∑h∈Iπ−iσ(h)∑z⊒hπσ(h→z) ui(z) v_i(\sigma,I)=\sum_{h\in I}\pi^{\sigma}_{-i}(h)\sum_{z\sqsupseteq h}\pi^{\sigma}(h\to z)\,u_i(z)
                          rt(I,a)=vi(σt,I,a)−vi(σt,I). r^t(I,a)=v_i(\sigma^t,I,a)-v_i(\sigma^t,I).

                          Theorem. Total regret is at most the sum of these local regrets, so

                          RiTT  ≤  Δ ∣Ii∣∣A∣T. \frac{R_i^T}{T}\;\le\;\frac{\Delta\,|\mathcal I_i|\sqrt{|A|}}{\sqrt T}.

                          The average strategy weights each iteration by our own reach:

                          σˉ(I,a)=∑tπiσt(I) σt(I,a)∑tπiσt(I). \bar\sigma(I,a)=\frac{\sum_t\pi_i^{\sigma^t}(I)\,\sigma^t(I,a)}{\sum_t\pi_i^{\sigma^t}(I)}.

                          So CFR converges to Nash, at a cost that grows with the number of infosets: big trees converge slowly.

                          🔍 Go deeper: the decomposition idea and the code

                          Change the strategy one infoset at a time, from the leaves up. A change at II only affects II's subtree, which carries weight πi(I) π−i\pi_i(I)\,\pi_{-i}. Since πi≤1\pi_i\le1, the gain is at most the counterfactual gain. The total gain telescopes into the sum of the local ones.

                          def cfr(h, i, pi_i, pi_opp):           # player i's value at history h
    if terminal(h): return u_i(h)
    if chance(h):   return sum(p * cfr(h+c, i, pi_i, pi_opp * p) for c, p in outcomes(h))
    I = infoset(h); sigma = regret_matching(R[I])
    if player(h) == i:
        v_a = {a: cfr(h+a, i, pi_i * sigma[a], pi_opp) for a in actions(I)}
        v = sum(sigma[a] * v_a[a] for a in actions(I))
        for a in actions(I):
            R[I][a] += pi_opp * (v_a[a] - v)        # counterfactual regret
            S[I][a] += pi_i * sigma[a]              # average-strategy numerator
        return v
    return sum(sigma[a] * cfr(h+a, i, pi_i, pi_opp * sigma[a]) for a in actions(I))

                          1.7.5 CFR+ and friends

                          CFR+ (Tammelin, 2014) floors regrets at 0 (Q←max⁡(Q+r,0)Q\leftarrow\max(Q+r,0)), weights iteration tt by tt, and alternates the players. It is often closer to 1/T1/T in practice, and it is what solved heads-up limit Hold'em (2015). Discounted CFR tunes those weights further.

                          1.7.6 Ranges as arrays: the vector form

                          In poker the betting is public and only the cards are private. So walk the public tree and carry a range vector ri[h]r_i[h] over every private hand. A showdown becomes a single matrix product:

                          v=w (M ropp) v = w\,(M\,r_{\text{opp}})

                          Here M[h,h′]M[h,h'] is +1+1 if hh beats h′h', −1-1 if it loses, and 00 for a tie or when the two hands share a card.

                          A Discard Hold'em river is 903×903903\times903 entries per showdown: a few NumPy operations per iteration. That is perfect for vectorisation and for GPUs, and it is how real-time river solvers work. Sorting hands by strength turns the O(n2)O(n^2) product into an O(n)O(n) cumulative sum.

                          Monte Carlo CFR samples part of the tree per iteration and stays unbiased through importance weights.

                          External samplingcards + the opponent's movesthe usual default; the weights cancel

                          1.7.8 Trust, but verify

                          On small games (Kuhn, Leduc, one river) compute exact exploitability: it must fall toward 0. On large games use local best response and head-to-head matches. Never trust a solver that has never matched a known answer.

                          Key idea

                          Regret matching at every infoset, driven by opponent-and-chance-weighted values, makes the average strategy converge to Nash. Vectorise over hands; sample when the tree is huge.

                          1.8 Abstraction, subgame solving and PIMC

                          Discard Hold'em has more histories than atoms in the universe. Every bot cheats, by solving a smaller game.

                          1.8.1 Card abstraction

                          A card abstraction sorts hands into buckets that share one strategy. Simple buckets use equity; better ones cluster equity histograms, so that draws and made hands stay apart. Most are imperfect-recall, forgetting earlier buckets to save memory.

                          1.8.2 Action abstraction

                          Keep a few bet sizes, say ½ pot, pot and all-in. An off-tree bet xx between sizes A<x<BA<x<B is mapped to them by action translation, usually the pseudo-harmonic mapping:

                          P(treat as A)=(B−x)(1+A)(B−A)(1+x). P(\text{treat as } A)=\frac{(B-x)(1+A)}{(B-A)(1+x)}.
                          Pitfall: abstraction error

                          Real exploitability = solving error + abstraction error. More iterations fix only the first. This is exactly how the repository's CFR attempt failed (Chapter 2).

                          1.8.3 Subgame solving

                          Superhuman bots play a coarse blueprint early, then re-solve the rest of the hand in real time. Unsafe subgame solving trusts the entry ranges; safe versions add a gadget so the result is never worse than the blueprint. The river is the ideal subgame: no cards to come, 903 hands, a short tree. The entry ranges can come from any opponent model.

                          1.8.4 PIMC

                          Perfect-information Monte Carlo: sample the hidden cards, solve each sample as if you could see them, and average the results. It is great for a discard, where both cards are revealed anyway. It is bad for bluffing, because of strategy fusion: in every sample it "knows" the cards, so it never values hiding them.

                          Equilibrium is the fortress. Exploitation is the raid. This section is about raiding without getting ambushed.

                          1.9.2 Lean on the model, but not too hard

                          A best response to a model is pure and extreme, which makes it fragile if the model is wrong. A restricted Nash response (RNR) solves a game in which the opponent must follow the model with probability pp:

                          p=0: equilibrium⟷p=1: best response to the model. p=0:\ \text{equilibrium} \qquad\longleftrightarrow\qquad p=1:\ \text{best response to the model}.

                          In between it gets most of the gain for little risk. Data-biased response sets pp per spot by how much data backs it. Safe exploitation only risks the "gifts" already won.

                          1.9.3 Notice when you're wrong

                          A bail-out monitor watches for evidence against the model, for example Page's CUSUM:

                          St=max⁡(0,  St−1+ℓt),alarm when St>h. S_t=\max\bigl(0,\;S_{t-1}+\ell_t\bigr),\qquad \text{alarm when } S_t>h.

                          1.9.4 Exploit in proportion to confidence

                          Let the exploitation strength λ∈[0,1]\lambda\in[0,1] grow with the posterior, and drop it on an alarm. "Caught" means confident, never assumed.

                          1.9.5 Play for the match, not the chips

                          Points come from winning matches. Over nn hands with edge μ\mu and noise σ\sigma:

                          P(win)≈Φ ⁣(μnσ). P(\text{win})\approx\Phi\!\left(\frac{\mu\sqrt{n}}{\sigma}\right).
                          • Only μ/σ\mu/\sigma matters: a wild exploit can lower P(win).
                          • Ahead late? Cut variance. The extreme form is the endgame lock: once the lead beats every blind left, check-fold to a guaranteed win.
                          • The tie-break caps each match at ±C chips: margin past the cap is wasted risk.

                          1.10 Self-improvement: self-play, leagues, honest tests

                          "Make the bot face a slightly better bot, forever." Great idea, if the game is transitive. Poker isn't.

                          1.10.1 Self-play

                          Fictitious play best-responds to the opponent's average past play and converges in zero-sum games. Naive "beat your latest self" has no such guarantee.

                          1.10.2 Non-transitivity

                          A calling station beats a heavy bluffer. A heavy bluffer beats a tight player. A tight value-better beats a calling station. That is rock-paper-scissors again (Section 1.6.1). A relation is transitive if A beats B and B beats C imply A beats C; poker styles are not. Big game studies describe a spinning top: a skill axis with cycles around it. Progress means climbing the axis, not circling.

                          1.10.3 Leagues

                          Double oracle and PSRO keep a population and its meta-game of head-to-head results, solve that for a mixture, and add a best response to it. AlphaStar's league adds roles: main agents trained by prioritised fictitious self-play, main exploiters, league exploiters, and frozen past selves. Rocket League bots learn by deep RL on billions of frames; with little compute, the realistic version is a league over parameters.

                          1.10.4 Ratings

                          Elo assumes one number per player, and so assumes transitivity:

                          P(A beats B)=11+10−(RA−RB)/400. P(A\text{ beats }B)=\frac{1}{1+10^{-(R_A-R_B)/400}}.

                          With cycles, report the full results matrix, or use Nash averaging.

                          1.10.5 Search under noise

                          Random search, CMA-ES, successive halving and Hyperband all spend more samples on promising candidates. Every search overfits, so three guards apply: fresh-seed re-tests, a held-out set you rarely look at, and "no opponent worse by 2 SE".

                          Key idea

                          Self-improvement needs a population (past champions, exploiters, outsiders), a budget (successive halving) and a gate (fresh seeds, no regressions, a held-out set).

                          2.9 Catching a bot: how fast?

                          Show the identification table
                          • Identity is fast but optimistic. 13 of 17 bots are pinned within 20 hands, but only because they are in the library. The starter and calling_station bet identically, as do tier1 and tier2, and the right exploit is the same within each pair. A real opponent will be matched to its nearest neighbour, with too much confidence.
                          • Traits are the robust signal. Over-folding is confirmed in about 40 hands against exploiter and rules, and about 110 against conv_opp3. Stations are confirmed in about 18.
                          • "Never bluffs the river" is too slow to measure. It needs showdowns of river bets: about 1 per 26 hands against exploiter, so about 500 hands for a verdict, longer than a match.
                          Catch fast traits, infer slow ones

                          In this pool every over-folder is also a value-only river bettor. A type library turns the 40-hand observation into a belief about the 500-hand one. That is why catching the bot matters: the type tells us things the match is too short to measure.

                          2.10 The exploit layer (design)

                          2.10.1 Rules of the design

                          • Traits first, type second. SPRTs on fast traits; a naive Bayes type posterior with an explicit "unknown" class to infer the slow traits.
                          • λ per counter-move (§1.9.4): cheap-when-wrong moves (fold a bluff-catcher) switch on early; costly ones (bluff every river) need a decided SPRT.
                          • Bail-out: a CUSUM on predicted versus observed folds. Important because d_new_exploiter adapts too.
                          • Play for the match: late with a lead, shrink variance; margins past the tie-break cap (400 / 1,000 chips) are worth nothing.

                          2.11 A self-improving loop: Claude's proposal

                          Proposal

                          For you to argue with, not a decision. "Face a slightly better bot and keep learning" is right in spirit; Section 1.10 explains why it needs a population and a gate.

                          • What evolves: numbers only (Tier 3's parameters plus the exploit layer's thresholds and λ schedule). Code changes stay human decisions.
                          • Score: match points with the lock on, as shipped; chips/hand as the low-variance tie-breaker.
                          • League: frozen past champions (catch cycles, §1.10.2), the training pool + starter + sparring (anchor to outside bots), exploiters (§1.10.3), and 2–3 fresh LLM bots every few generations, which also form a new held-out set.
                          • Stop after three generations with no promotion, or gains within 1 SE.
                          Risks

                          Overfitting to Claude-written bots (7 of 9 come from one model family; add bots from other models and keep the starter). Multiple testing (16 candidates per generation, hence the fresh-seed gate). Compute: about 100–140 generations in two weeks, enough to tune dozens of numbers, not to discover new strategy.
